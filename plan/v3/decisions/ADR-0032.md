# ADR-0032: sweep() returns entries EVICTED, and a server-expiring provider honestly returns 0

- **Date:** 2026-08-04
- **Status:** Accepted
- **Scope:** `sweep()` on the cache backends in all four frameworks.
- **Relates to:** [ADR-0024](ADR-0024.md) (the swap must work, rule 3: no
  provider may silently do less).

## The decision

> **`sweep()` exists on EVERY provider and returns an integer: the number of
> expired entries it actually removed.**
>
> - Providers that hold entries locally (memory, file, database) really evict
>   and return a real count.
> - Providers that expire entries SERVER-SIDE (redis, valkey, memcached,
>   mongodb) return 0, because nothing was evicted - there was nothing left to
>   evict.

## The defect this closes

Measured 2026-08-01, re-measured at `v3` HEAD 2026-08-04. `sweep()` behaved
three different ways across the family:

| framework | behaviour |
| --------- | --------- |
| python | real counts on memory and file, 0 elsewhere |
| php | real counts on memory and file, 0 elsewhere |
| ruby | **`NoMethodError` on 6 of 7 providers** - only the file backend had it |
| nodejs | **a permanent 0** - the module function called a backend `sweep` that no backend defined |

A monitoring dashboard reading that number is reading three different things,
and one of them is a crash. It is also ADR-0024 rule 3 twice over: a method
absent on six providers cannot even reach a refusal, and a permanent 0 is a
method that exists and no-ops.

## The 0 is a real answer, not a shrug

This is the part worth writing down, because "return 0" looks like the exact
silent no-op ADR-0024 rule 3 forbids.

It is not, and the distinction is the definition of the return value. `sweep()`
returns **how many entries THIS CALL removed**, not how many expired. On Redis
the server has already reclaimed them; there is nothing for the client to
remove, so 0 is the true count. A caller polling `sweep()` on a redis-backed
cache and seeing 0 is being told the truth: your cache needs no help.

The alternative - raising "unsupported" on the network providers - was rejected.
It would force every caller to write the provider conditional that ADR-0024 rule
1 exists to abolish, and there is nothing wrong to report: the operation
succeeded and reclaimed nothing.

## A defect found while proving it: the DATABASE backend is not server-expiring

Python is the reference implementation and Python was wrong here, so it was
FIXED rather than mirrored outward.

`_DatabaseBackend` had no `sweep()` and inherited the base class's 0. But a SQL
table expires nothing by itself. Expired rows were deleted only when someone
happened to read that exact key again, so `tina4_cache` grew without bound while
the one API whose job is reclaiming that space reported success having done
nothing - and `stats()["size"]` counted the dead rows as live.

The database backend belongs in the locally-held column, not the server-expiring
one, and now sweeps for real.

**`expires_at > 0` is load-bearing.** An entry stored with `ttl <= 0` is
permanent and carries 0, so a bare `now > expires_at` evicts every permanent
entry on the first sweep - silently, and reported as a successful reclaim. That
is pinned by a negative test in all four (`sweep leaves entries without a ttl
alone`) and is one of the mutation proofs.

## How it is held

`plan/v3/fixtures/cache_contract.json`, invariant
`sweep-returns-a-real-count-everywhere`, with the four suites it names. The
negative cases are what stop the obvious wrong implementations: a sweep with
nothing expired must return 0 rather than the total entry count, and a no-TTL
entry must survive.
