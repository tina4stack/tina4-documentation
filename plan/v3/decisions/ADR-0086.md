# ADR-0086: One SQLite database-path resolver across the four frameworks

- **Status:** Accepted
- **Date:** 2026-09-27
- **Scope:** tina4-python, tina4-php, tina4-ruby, tina4-nodejs (SQLite path resolution)
- **Decision owner:** Andre van Zuydam
- **Governs fixture:** `plan/v3/fixtures/sqlite_path_contract.json`
- **Supersedes:** nothing. No accepted ADR decided SQLite path resolution before
  this one; it writes the contract down for the first time.

## Context

Every framework turns a SQLite connection string into a path the driver opens.
The path resolver was just deduplicated into one home per language: the PHP
`Tina4\Database\ResolvesDatabasePath` trait, the Ruby
`Tina4::SqlitePathResolver` module, Python `Database._connection_path`, and the
Node `resolveSqlitePath` function. Deduplication made each language internally
consistent. It did not make the four agree with each other.

The four already agree on the common shapes. `:memory:` passes through
untouched. A unix-absolute path (`/var/data/app.db`) passes through and is the
caller's responsibility. A relative path resolves under the current working
directory (the project root). They disagree on the edges, and one edge is a
latent security-relevant footgun.

1. **The mkdir mode.** PHP asks for `0775` when it creates a parent directory.
   Python, Ruby and Node take whatever the operating system umask hands them,
   so the same relative path produces a different directory mode depending on
   which framework wrote it.

2. **The escape guard.** This is the footgun. Python guards the auto-create with
   a containment check and will not create a parent that resolves outside the
   project root, but it still returns the escaping path, so the driver fails
   later with an opaque "unable to open database file". PHP and Ruby `mkdir` the
   parent of a relative path unconditionally, with no guard at all, so a string
   such as `../../etc/foo.db` makes them silently create directories outside the
   project. Node creates a directory only when the target sits under the project
   root, so it neither escapes nor complains. Three different answers to one
   input, and two of them touch the filesystem outside the project without
   saying so.

3. **The drive-letter path on a POSIX host.** PHP, Python and Ruby recognise a
   Windows drive-letter path (`C:\` or `C:/`) with an explicit test and pass it
   through. Node uses `path.isAbsolute`, which does not recognise `C:/` on a
   POSIX operating system, so Node re-roots the drive-letter path under the
   project and creates a stray `C:/` tree.

## Decision

One resolution contract, obeyed by all four frameworks. A connection string
becomes a path by these rules, in order.

1. **`:memory:` passes through.** The URL forms `sqlite::memory:` and
   `sqlite:///:memory:` resolve to `:memory:` and touch no filesystem.

2. **An absolute path passes through, and nothing is created.** A path is
   absolute when it is unix-absolute (a leading `/`) or a Windows drive-letter
   path matching `^[A-Za-z]:[\\/]`. The drive-letter form is recognised on every
   operating system, POSIX included, so the four never disagree by platform. An
   absolute path is the caller's own location; the framework will not create a
   directory for it.

3. **A relative path resolves under the project root.** The resolver joins it
   onto the current working directory and creates the parent directory with
   mode `0775` (which the umask still narrows, so a strict umask is honoured;
   the framework asks for `0775`, it does not force past the umask).

4. **A relative path whose parent escapes the project root is refused.** When
   the resolved parent is not the project root itself and not a descendant of
   it, the resolver raises a clear error naming the offending path, the project
   root, and the remedy. It never creates a directory outside the project, and
   it never returns a path that only fails cryptically when the driver opens it.

The error the four raise is the language's own argument error
(`ValueError` in Python, `InvalidArgumentException` in PHP, `ArgumentError` in
Ruby, a plain `Error` in Node), with the same wording: the path resolves
outside the project directory, and an absolute path is the way to point at a
database that lives outside the project.

## Why refuse, not clamp, and not silently skip

An escaping relative path has three defensible answers, and the choice was the
one genuinely contentious point.

- **Clamp** rewrites `../../etc/foo.db` into something under the project. It
  silently changes what the caller asked for and could collide with an unrelated
  file already in the project, so a mistake becomes a different, quieter
  mistake.
- **Silently skip** the mkdir and hand the path on, which is what Python did.
  The escaping directory is not created, but the escaping path is still
  returned, so the failure surfaces as the driver's opaque open error with no
  hint of the cause.
- **Refuse** names the problem where it happens, with the fix in the message.

Refusing wins because it is the only answer that is both safe and honest. It
does change one behaviour: a relative path that pointed at an existing sibling
directory outside the project, such as `../shared/app.db`, used to work on PHP
and Ruby and now raises. That is the deliberate cost, and the remedy is one line
in the message: use an absolute path for a database that lives outside the
project. The four headline shapes (`:memory:`, unix-absolute, relative under the
root) are unchanged.

## Consequences

- The PHP trait and the Ruby module gain the containment guard Python already
  had, and now refuse rather than create outside the project. All four ask for
  mode `0775`. Node gains an explicit drive-letter test so `C:/` passes through
  on a POSIX host, and stops creating a directory for an absolute path so it
  matches the other three.
- The shared fixture `sqlite_path_contract.json` enumerates the five cases
  (`:memory:`, unix-absolute, drive-letter-absolute, relative-under-root with
  the parent created at `0775`, and relative-escaping refused with nothing
  created). Each framework carries a real regression test, no mocks, that proves
  the new behaviour, and the escape refusal in particular is proven to raise.
- The escape refusal closes a path-traversal footgun in PHP and Ruby: a
  connection string is a trust boundary, and a relative one could make the
  framework write directories anywhere the process could reach.
