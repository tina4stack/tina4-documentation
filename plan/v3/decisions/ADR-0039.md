# ADR-0039: ext-interbase is built from source, not deleted

- **Date:** 2026-08-05
- **Status:** Accepted
- **Scope:** `tina4-php/Tina4/Database/FirebirdAdapter.php` (the native branch),
  the 12 PHP tests gated on `ext-interbase`, and the lab's PHP 8.3 runtime.
- **Relates to:** [ADR-0037](ADR-0037.md) (the no-skip gate is a deny-list) -
  this ADR supplies the decision ADR-0037 was explicitly blocked on.
  [ADR-0038](ADR-0038.md) (one canonical `TINA4_TEST_*` set).

## The problem, measured

`FirebirdAdapter.php:116-151` selects a **native** Firebird path through
`ibase_*` when `ext-interbase` is loaded, and falls back to
`PdoFirebirdAdapter` otherwise. On PHP 8 no supported build could reach the
native branch, so every live Firebird test resolved to PDO and 12 tests skipped
outright. Measured on the lab, PHP 8.3.6:

| probe | result |
| ----- | ------ |
| `pecl search interbase` | no packages found |
| `pecl search firebird` | `PDO_FIREBIRD 0.2` (beta) only |
| `php8.3-interbase` (Ubuntu) | ships **only** `pdo_firebird.so` |
| `function_exists('ibase_connect')` | false, not compiled in |
| `function_exists('fbird_connect')` | false |
| `/usr/include/ibase.h` | **present** (from `firebird-dev`) |
| `phpize`, `php-config`, `gcc`, `make` | **all present** |

The 12 skipping tests:

    tests/DatabaseDriversTest.php:193, :497, :511, :589
    tests/FirebirdOrmWriteTest.php:41
    tests/FirebirdOrmCountTest.php:42
    tests/FirebirdWriteVisibilityTest.php:94
    tests/MigrationV3Test.php:187, :204
    tests/PdoFallbackParityTest.php:293
    tests/MigrationFootgunsLiveEngineTest.php:245

So the extension was **not distributed** for PHP 8, but every build
prerequisite was already installed. That gap is the whole decision.

## The decision

**Build `ext-interbase` from source. Do not delete the native branch, and do
not rewrite the 12 tests against PDO.**

The native driver exists because it is more efficient than PDO: it talks to
`libfbclient` directly with no PDO abstraction layer in the request path. That
performance is the reason the branch was written, and a distribution decision by
one vendor is not a reason to discard a working code path. "The distro stopped
packaging it" is a packaging fact, not an engineering one.

The two alternatives were considered and rejected:

| option | why rejected |
| ------ | ------------ |
| delete the native branch, make PDO the only Firebird path | Throws away the performance the branch exists for. Deleting code that works to avoid building it is the wrong trade when the build prerequisites are already present. |
| keep the branch, rewrite the 12 tests against PDO | Leaves the native path shipped and permanently unexercised. That is worse than a skip: the tests would go green while testing the other adapter entirely. |

Both would have been chosen on "less code" grounds. Less code is the tiebreak
when other things are equal, and here they are not: one option deletes a
deliberate optimisation, the other ships an untested code path.

## What the build actually took

Source: **`github.com/php/pecl-database-interbase`**, pinned at commit
`05049db61daf4bac6ca7d02591a86284644cde90`. Dormant since 2019 and never
published as an installable PECL package, so it is fetched as a git tarball.

**Correction to a common assumption:** `ext/interbase` was removed **in** PHP
7.4, not after it. `php-7.4.33.tar.gz` does not contain it; 7.4's `UPGRADING`
records that the extension moved to PECL. The last core copy is in PHP 7.3.
The PECL repo is already partly modernised (it ships real hand-written arginfo,
which PHP 8 requires, and already uses `zend_register_resource()` /
`zend_fetch_resource()` rather than the deleted `ZEND_REGISTER_RESOURCE` /
`ZEND_FETCH_RESOURCE` macros), so most of the expected PHP 8 breakage did not
apply. Three patches were needed:

| patch | why |
| ----- | --- |
| `0001-php8-tsrmls-ctx-macros.patch` | **Required, and it fixed a latent crash.** PHP 8 deleted `TSRMLS_SET_CTX()` and `TSRMLS_FETCH_FROM_CTX()`. Being function-like names, their absence compiled as *implicit declarations* (warnings only) and still LINKED, producing an `interbase.so` with two undefined symbols. That is a process abort on the first `ibase_set_event_handler()` or `ibase_wait_event()` call. Restored under `#ifndef` guards. |
| `0002-firebird3-isc-event-block-ptr-types.patch` | Firebird 3.0+ changed `isc_event_block()` to take `ISC_UCHAR**`; the extension still passes `char**`. A warning on gcc 13.3, but gcc 14 promoted `-Wincompatible-pointer-types` to an error, so the build fails without it on Ubuntu 24.10+ and Fedora 40+. |
| `0003-gnu-source-redefinition.patch` | Cosmetic. PHP 8's build system already defines `_GNU_SOURCE`. |

Final build: **0 errors, 0 warnings.**

The one non-obvious configure step is `./configure --with-interbase=/usr`.
`config.m4` defaults to `/opt/firebird`, and passing an explicit path
deliberately bypasses its `fb_config` branch, which only fires for `=yes`.

Patch 0001's ZTS branch is written but **not exercised** on this runtime, which
is NTS. That is a declared gap, not a claim.

## Verification

Verified twice, independently: once by the build, and once by a separately
written probe so that a green is a second observation rather than a re-run of
the build's own proof.

    php -m | grep -i interbase                            -> interbase
    php -r 'var_dump(function_exists("ibase_connect"));'  -> bool(true)
    nm -D --undefined-only interbase.so | grep TSRMLS     -> empty (patch 0001 holds)

Real round trip against the live lab Firebird **5.0.4** at
`127.0.0.1/3050:/var/lib/firebird/data/tina4test.fdb`, no mocks: connect,
`CREATE TABLE`, `INSERT`, `SELECT` returning real rows, prepared statement with
a bound parameter, `DROP TABLE`, commit, close.

`PDO_Firebird` remains loaded alongside it, so the PDO path is unaffected and
the adapter's fallback still resolves as before.

## A Firebird semantic worth recording

Committing a `DROP TABLE` while a `SELECT` result handle on that table is still
open produces:

    ibase_commit(): unsuccessful metadata update object TABLE "..." is in use

The drop still applies. This is Firebird engine semantics, not an extension
defect, and it is reproducible on both adapters. It matters because any code
path that runs DDL without first freeing its result handles will hit it, and
migrations and `tableExists()` are the likely places.

## What this unblocks in ADR-0037

ADR-0037 stays **Proposed** for one stated reason: the skip roster must be down
to its acceptable set before the gate can be inverted, and "PHP is not, and its
dominant blocker (12 skips on `ext-interbase`) needs a decision, not a
configuration change." **This ADR is that decision.**

It also **retires ADR-0037's `ext-interbase not installed` row**, which reads:

> The `ibase_*` API left PHP core in 7.4 and has no PHP 8 build ... Unrunnable
> on any supported PHP.

The first half is accurate. The conclusion is not: there is no PHP 8
*distribution*, which is not the same as no PHP 8 *build*. It builds from the
PECL source with three patches, and the prerequisites were already installed on
the runner. ADR-0037's Consequences section further proposed that "the native
path should be dropped or documented as PHP 7.x-only" - that recommendation is
**superseded**. The path is kept and is now exercised.

The same correction applies to the rest of that table. Four more rows describe
skips as permanently unfixable that are in fact reachable, and each is being
closed in the same pass as this ADR:

| ADR-0037 row | Why it is no longer acceptable |
| ------------ | ------------------------------ |
| `running as root` - "Fixable only by running the suite as a non-root user" | False. A privilege-dropping child (fork + `setuid`, or `setpriv`) produces a real `EACCES` without changing how any suite is invoked. The parent stays root; only the assertion runs unprivileged. |
| `cannot test missing extension error` - "can never run on a fully-provisioned box" | False, and the counter-example was already in the tree: `tests/SessionZeroDependencyFallbackTest.php` runs the case in a real child with `PHP_INI_SCAN_DIR` pointed at a `conf.d` copy minus the relevant `.ini`. That is genuine absence on a fully-provisioned box. |
| `drive-letter form` / `POSIX-shaped` | A path parser is a pure function. It needs Windows-shaped INPUT, not a Windows HOST, so the case is testable on Linux. |
| `needs a real MinIO` - "the one service the lab genuinely does not run" | No longer true. `tina4-lab-minio` is up on host port 9100. The row itself demanded "either provision it or keep this entry - but say which": it is provisioned. |

The general lesson is the one ADR-0037 already states about greps, pointing at
itself: **an enumeration of things believed impossible is a hypothesis, not
evidence.** Five of its six rows were environment facts that had gone stale or
technique gaps, not laws. Only the deny-list polarity it proposes survives
unchanged - and with the roster at zero, `ACCEPTABLE_SKIPS` can start empty,
which is the strongest form of the gate it asked for.

## Consequences

- **Users on PHP 8.2+ must build the extension** to get the native path; there
  is no package. The fallback to `PdoFirebirdAdapter` means they are not broken
  without it, only slower. The build is scripted and reproducible from the
  patches rather than hand-applied on one box.
- **The upstream is dormant** (no commits since 2019). Tina4 now carries the
  patch set that makes it build on PHP 8. That is a real maintenance liability
  and is accepted deliberately, in exchange for keeping the faster path.
- **The 12 tests must now RUN**, and with them the native branch is exercised on
  PHP 8 for the first time. Any native-versus-PDO divergence against the same
  live Firebird is a defect in one of the two adapters, not a test problem;
  `tests/PdoFallbackParityTest.php:293` is the test that compares them.
- The gate change matters as much as the build: while `ext-interbase` was
  absent, `DatabaseDriversTest.php:193` RAN (it asserts the missing-extension
  error). Now that the extension is present, that test inverts and would skip.
  It is covered by the `PHP_INI_SCAN_DIR` subprocess technique already used in
  `tests/SessionZeroDependencyFallbackTest.php`, which builds a child from a
  copy of `conf.d` with the relevant `.ini` omitted, giving genuine absence
  rather than a double.
