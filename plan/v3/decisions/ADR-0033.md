# ADR-0033: A missing DocStore driver raises - it never falls back to the local file

- **Date:** 2026-08-04
- **Status:** Accepted
- **Scope:** `DocStore` provider resolution in all four frameworks.
- **Relates to:** [ADR-0024](ADR-0024.md) (the swap must work, rule 3),
  [ADR-0025](ADR-0025.md) (the fallback imitates the driver),
  [ADR-0012](ADR-0012.md) (settle contracts against real-world frameworks).

## The problem, measured

`docstore_contract.json` has carried this as the last owed invariant since
2026-08-01:

> URI configured + driver absent produces the SAME outcome in all four
> frameworks, and that outcome is loud.

Re-measured 2026-08-04 at `v3` HEAD (python 75cb10b, php 867838a5, ruby
b15749c, nodejs b23bf29), in genuinely driverless environments - no mocks, no
monkeypatched imports, no faked `ImportError`. Nothing had changed:

| framework | driverless environment used | outcome with `TINA4_MONGO_URI` set |
| --------- | --------------------------- | ---------------------------------- |
| python | `python -m venv` with no `pymongo`, framework on `PYTHONPATH` | `is_serverless()` -> **True**, `get_collection()` -> **SqliteCollection**. Silent. |
| php | `php -n`, so `ext-mongodb` is genuinely not loaded | `isServerless()` -> **true**, `getCollection()` -> **Tina4\SqliteCollection**. Silent. |
| ruby | isolated `GEM_HOME` holding `sqlite3` and not `mongo` | `serverless?` -> **true**, `get_collection` -> **SqliteCollection**. Silent. |
| nodejs | the module built into a directory outside the repo, where `mongodb` is genuinely unresolvable | `isServerless()` -> false, `getCollection()` **throws `ERR_MODULE_NOT_FOUND: Cannot find package 'mongodb'`**. Loud, but undocumented and unnamed. |

One env, two shapes, four messages. Three frameworks send production writes to
a container-local SQLite file that nobody reads and that vanishes on the next
deploy. The fourth crashes with a module-resolution error that names an npm
package rather than the framework decision that led there.

### PHP had a second silent door

`isServerless()` gates on `\MongoDB\Driver\Manager` (the PECL extension) but
`getCollection()` then needs `\MongoDB\Client` (the `mongodb/mongodb` composer
library), and when only the second is missing it *also* returned the local
store. That is not hypothetical: `mongodb/mongodb` is `require-dev` plus a
`suggest` in `composer.json`, so a production `composer install --no-dev` on a
box that does have the extension lands exactly there.

## The decision

> **When a Mongo URI is configured and the driver is absent, DocStore RAISES a
> named, documented error at provider resolution. It never returns the local
> SQLite collection.**

This is ADR-0024 rule 3 applied without exception: *a provider that cannot
honour an operation must RAISE, naming the provider and what is missing.*

1. **One error, four spellings of the same name:** `DocStoreDriverMissing`.
2. **One message**, identical in shape across the four, differing only in the
   package name and the install command:

   ```
   Tina4 DocStore: <ENV_VAR> is set, so the MongoDB provider is selected, but
   its driver is not installed (<what>). Install it with `<command>`, or unset
   <ENV_VAR> to use the local SQLite store.
   ```

   `<ENV_VAR>` is the variable that actually supplied the URI, so the operator
   is told which one to unset.

3. **The URI VALUE is never in the message.** A Mongo URI routinely carries
   `user:password@`, and an error string is the most-copied, most-logged,
   most-pasted-into-a-ticket text a framework produces. The variable is named;
   its contents are not. Every framework's test asserts this negatively.

4. **`is_serverless()` becomes configuration-only in all four.** It used to
   answer "is the SQLite fallback in effect", computed partly from driver
   presence, which is exactly what made three frameworks answer "serverless,
   yes" and hand back a local file. It now answers "is a Mongo URI configured",
   full stop.

   Without this the fix has a second door: an app branching on
   `if is_serverless(): ...local... else: ...mongo...` would take the local
   branch and never reach the raise. **Node was already right here** - its
   `isServerless()` already reflected configuration only - so the other three
   move to Node's semantics. Python is the master on internal API design, and
   on this one point Python was the broken one and was fixed rather than
   mirrored outward.

5. **No network I/O is added to resolve a provider.** A missing driver is a
   static fact, knowable without a socket, so the raise happens at resolution.
   An unreachable *server* is a different failure and keeps its existing
   driver-native behaviour.

## Why not degrade, given the cache degrades?

Tina4's cache deliberately falls back to the file backend when a driver is
missing, and it is fair to ask why DocStore does not.

Because the blast radius is not comparable. **A cache is disposable by
definition** - degrading it costs latency, and every entry is reconstructible
from the source of truth. **A document store IS the source of truth.** Writes
that land in the wrong place are not slow, they are gone, and nothing upstream
ever reports an error. ADR-0024 rule 3 is about a provider that cannot honour
an operation; a local SQLite file honours `insert_one` in form and destroys its
meaning.

The second reason is discoverability. A missing cache driver announces itself
the moment anyone looks at hit rates. A missing DocStore driver announces
itself when someone asks where last quarter's orders went.

## What this does NOT decide

**DocStore has no zero-dependency wire-protocol fallback in any framework, and
this ADR does not add one.** Measured 2026-08-04: the hand-rolled MongoDB
`OP_MSG` transport exists only in the *session* handlers (python, php, nodejs)
and PHP's cache backend - never in DocStore. So the three-state model
(driver / wire fallback / raise) collapses to two states here, symmetrically in
all four, and nothing is being papered over: no framework is being made to
degrade to match another.

Whether DocStore should grow the wire fallback the session layer already has -
which would let the zero-dependency promise hold for documents as it does for
sessions - is real work with a real design, and it is **recorded as owed**, not
decided here. It is also entangled with the session contract's own owed
invariant `zero-dependency-fallback-in-every-framework` (ruby has no wire
fallback where the other three do), and should be settled with it rather than
twice.

## Consequences

- **Breaking.** An app that today runs on the silent SQLite fallback with a
  Mongo URI set and no driver installed will now raise at the first
  `get_collection()`. That is the point: it was never doing what its operator
  believed. The migration is one of two lines - install the driver, or unset
  the URI - and ships as a `Breaking:` changelog entry with that text in all
  four frameworks.
- `docstore_contract.json :: a-missing-driver-has-one-outcome-in-all-four`
  moves from OWED to PROVEN, taking the fixture to zero owed.
- The tests that prove it may not fake an absent driver. Each framework builds
  a REAL driverless environment and asserts, first, that the environment really
  is driverless - so a leaky environment FAILS the test instead of quietly
  proving nothing.
