# ADR-0075: Tina4 moves to MPL-2.0 with a Code Infinity commercial licence

- **Status:** Accepted (pending legal review and contributor consent before it takes effect)
- **Date:** 2026-09-24
- **Scope:** tina4 (CLI), tina4-python, tina4-php, tina4-ruby, tina4-nodejs, tina4-js, tina4-documentation
- **Decision owner:** Andre van Zuydam (Code Infinity)

## Context

The licences today are inconsistent. The CLI, Ruby and documentation carry MIT licence files naming three different copyright holders. The Python, Node.js and tina4-js repositories have no licence file, though their package metadata says MIT. The PHP repository's licence file is GPL-3.0 while its `composer.json` says MIT. That inconsistency fails ISO/IEC 5230 on its own.

The maintainer also wants a licence that asks people who change Tina4 to give their changes back, while Code Infinity can offer the framework to companies that want no such obligation.

## Decision

1. From the next release, every Tina4 repository is licensed under the Mozilla Public License 2.0 (MPL-2.0). Anybody who modifies Tina4's own files and distributes the result must make those modifications available under MPL-2.0. Applications that use Tina4 without changing its files may use any licence.
2. Code Infinity may also license Tina4 under separate commercial terms (dual licensing).
3. The copyright holder named in every licence file and notice is Code Infinity.
4. Contributions are accepted under the Tina4 Contributor Licence Agreement (`docs/general/contributor-licence-agreement.md`), which lets Code Infinity offer them under both licences, with a `Signed-off-by:` line on every commit.
5. Releases already published keep the licence they were published under.

## Before it takes effect

- Legal review of the licence change, the commercial terms and the agreement text.
- Consent from, or a rewrite of the contributions of, every author whose copyright isn't held by Code Infinity. The author list comes from the git history of all seven repositories; it holds personal addresses, so it is kept privately.
- Then, in one release: replace every licence file with MPL-2.0; change `pyproject.toml`, `composer.json`, the gemspec, `package.json` and `Cargo.toml` to `MPL-2.0`; add the MPL notice to source files; add a commercial licence notice; update the "MIT licensed" footer on tina4.com.

## Consequences

- Improvements made by others to Tina4 itself come back to the project.
- Companies that build closed applications on Tina4 aren't affected, which keeps adoption open.
- A commercial licence gives Code Infinity a way to fund the work.
- Contributors sign an agreement before their first pull request merges, which adds a step for them.

## Alternatives considered

- **Stay on MIT.** Rejected: nothing asks for improvements to come back.
- **GPL-3.0 or AGPL-3.0.** Rejected: GPL barely reaches web applications, and AGPL would force every application built with Tina4 to publish its source, which would stop most companies using it.
- **A source-available licence (Business Source License).** Rejected: it stops Tina4 being open source, which works against adoption and against the OpenChain position.
