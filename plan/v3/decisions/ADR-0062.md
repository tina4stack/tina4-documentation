# ADR-0062: Agent-experience contract — import-hint fallback and generate-resolution transparency

Status: Proposed
Date: 2026-08-25
Ships in: 3.13.117

## Context

Two failure modes trip AI coding agents (and humans) working in a
Tina4 project, both because the framework silently transforms input
and then fails downstream with a message that does not name the
transformation:

1. **Wrong-guess imports** — a coder types
   `from tina4_python.route import get`. The real module is
   `tina4_python.core.router`. The failure is a bare
   `ModuleNotFoundError: No module named 'tina4_python.route'` with
   no hint about the true location. An agent has to reverse-engineer
   the layout from a stack trace or re-read the skill; a human types
   a random guess a second time.
2. **Silent generate transformations** — `tina4 generate model Order`
   auto-pluralises the table to `orders` because `order` is a SQL
   reserved word. The rename is documented in the source
   (`SQL_RESERVED_TABLE_NAMES`) but INVISIBLE to the caller. An agent
   that wrote a follow-up route `/order` or a raw SQL query against
   `order` fails downstream with no clue that the framework had
   already renamed the table under it. See tina4-python#123 for the
   design conversation that motivated this ADR.

Both are the same class of defect: the framework transforms without
telling the caller. This ADR ratifies a shared contract that makes
both transformations impossible to miss.

## Decision

### Part A - Import-hint fallback

Every backend ships a language-native LAST-RESORT hook that fires
ONLY when normal resolution failed. When triggered, the hook walks
the real installed source tree, computes the closest match, and
raises the language's canonical "not found" error with a hint
naming the correct module or class.

Contract invariants (uphold in every language):

1. **Fire-only-on-miss** — the hook is asked only after the normal
   resolver returned nothing. Zero cost on the happy path.
2. **Never-mask** — a real error raised INSIDE a module that DOES
   exist propagates untouched. The hook only sees names nothing else
   could resolve.
3. **Self-updating** — the "did you mean" list is derived from a
   walk of the real installed source tree, not a hand-maintained
   wrong-guess table. A framework rename updates the hint
   automatically.
4. **Bounded** — intervene only inside the framework namespace
   (`tina4_python.*`, `Tina4\\*`, `Tina4::*`, `@tina4/*`).
5. **Idempotent install** — the wire-up call is safe to invoke more
   than once.

Per-language mechanism:

| Language | Hook | File |
|----------|------|------|
| Python   | `sys.meta_path` finder appended LAST | `tina4_python/_import_helper.py` |
| PHP      | `spl_autoload_register` last-resort callback | `Tina4/ImportHelper.php` |
| Ruby     | `Tina4.const_missing` + `Kernel#require` wrap | `lib/tina4/import_helper.rb` |
| Node     | `package.json` `exports` wildcard tail + `_missing.js` | `packages/*/src/_missing.ts` |

**Node parity is deliberately weaker.** Node's `exports` wildcard
does not pass the requested subpath to the target file, so the hint
is a browsable list of real subpaths ("no such subpath under
`@tina4/core`; the real subpaths are `router`, `orm`, `frond`, ...")
rather than a targeted "did you mean `@tina4/core/router`?". This
asymmetry is accepted because:

- TypeScript users get a compile-time `Cannot find module` error
  directly from `tsc` — the runtime hint mainly helps plain-JS users.
- Node's ESM was never designed with a last-resort finder in the
  ecosystem-standard way that Python (`meta_path`), PHP (`spl_autoload`),
  and Ruby (`const_missing`/`require` wrap) all support.
- A targeted hint IS achievable via an opt-in `--import` loader hook,
  which we document but do not require.

### Part B - Generate-command resolution transparency

Every `generate` subcommand (model / route / migration / middleware)
in every language emits the resolved mapping in two shapes:

1. **Machine-readable JSON envelope** — with `--json`, stdout carries
   a versioned envelope, nothing else. Same shape across all 4
   languages (only the file-path extensions differ).
2. **Human-readable resolution block** — bare `generate` (no
   `--json`) writes files as before AND prints a resolution block
   to stderr naming every transformation, path, and warning.

Both are unconditional: the resolution is always available, whether
the model name is untransformed (`transformations: []`) or renamed
(`transformations: [{kind: reserved_word_pluralize, from: "order",
to: "orders", reason: ..., override: ...}]`).

Composable flags:

- `--dry-run` — compute resolution, DO NOT write files. Sets
  `dry_run: true`, `actions_taken: []`. Combines with `--json`.

The JSON envelope shape is a stable contract, advertised in the
existing `commands --json` manifest via a new
`resolution_contract` block:

```json
{"commands": [...],
 "resolution_contract": {"version": "1", "envelope": "generate_v1"}}
```

An agent can programmatically discover this contract, parse
`generate --json` output against schema `generate_v1`, and act on
the resolution without regexing human output. A future breaking
change to the envelope shape must bump the version.

### Envelope shape (identical across all 4 backends)

```json
{
  "command": "generate",
  "target": "model",
  "input": {"name": "Order", "fields": null},
  "resolution": {
    "class_name": "Order",
    "table_name": "orders",
    "file_path": "src/models/Order.<ext>",
    "migration_path": "migrations/<ts>_create_orders.sql",
    "transformations": [
      {"kind": "reserved_word_pluralize",
       "from": "order",
       "to": "orders",
       "reason": "SQL reserved word 'order' would break CREATE TABLE",
       "override": "--table-name <name> (names interpolate unquoted; a reserved name is yours to quote in SQL)"}
    ],
    "routes": ["/orders", "/orders/{id}"],
    "test_paths": ["<language-idiomatic test path>"]
  },
  "actions_taken": ["wrote src/models/Order.<ext>", ...],
  "dry_run": false
}
```

The reserved-word override is the `--table-name <name>` flag: it lets a
caller pick any table name explicitly. The quoted-identifier path an
earlier draft reserved (`--table X --quote`) is RESOLVED as rejected by
tina4-python#123 (see Resolution below); Tina4 never quotes identifiers.
The `override` field names `--table-name` so a caller knows what to type.

## Resolution: the deferred quoting question (tina4-python#123)

Status: Resolved. Ships in 3.13.129 across all four frameworks.

The reserved-word case posed one open question: keep the raw name via
quoted identifiers, or rename it. #123 decided RENAME, never quote.
Identifier quoting is a global storage invariant, not a local fix.
Quoting flips per-engine case-folding (PostgreSQL folds an unquoted name
to lower, Firebird to upper, MySQL is filesystem-dependent), and quoting
the DML while the introspection catalog lookup stays unquoted silently
returns no primary key, so a keyed write then matches every row or none.
That is data loss, not a syntax error, and it breaks every existing
unquoted schema on upgrade.

So Tina4 keeps the safe pluralise, removes the silent surprise (a loud
note now names the `order` to `orders` rename), and offers
`--table-name <name>` as the one escape hatch. A developer who forces a
reserved name owns the quoting in their own raw SQL. The inert `--quote`
flag is removed, and the `override` hint (machine envelope and human
block) points at `--table-name` in every language.

## Test contract

For every language, both features ship with real-subprocess tests
(no mocks, no in-memory monkey-patching that leaks across tests):

Import-hint (5 tests):

1. Positive-happy: legitimate import still works.
2. Positive-package: bare `import <framework>` still works.
3. Negative-hint: wrong guess raises with the correct target named.
4. Negative-no-match: wild guess still raises, message names real
   top-level modules.
5. Masking-gate: a REAL module that fails inside its own body raises
   the ORIGINAL body error, NOT the hint. Proves non-masking.

Generate-resolution (5 tests):

1. `--json --dry-run` for non-reserved name: valid JSON envelope,
   `dry_run: true`, `transformations: []`, no files written.
2. `--json --dry-run` for `Order`: `transformations[0].kind ==
   "reserved_word_pluralize"`.
3. Bare `generate model Foo`: files written AND stderr contains the
   resolution block.
4. Bare `generate model Order`: stderr contains "auto-pluralized"
   AND "SQL reserved word".
5. `commands --json` advertises
   `resolution_contract.version == "1"`.

Every negative test is proven a real gate via mutation.

## Consequences

- Wrong-guess imports become self-diagnosing. An agent that would
  have burned a round-trip debugging `ModuleNotFoundError` instead
  reads "did you mean X" in the same error and fixes on the next
  line.
- Generate transformations become inspectable BEFORE the agent acts
  on the generated files. `--dry-run --json` is a pre-flight the
  agent can call to know what mapping it will get.
- The stable `generate_v1` envelope is now a public contract.
  Breaking it requires an ADR-level version bump.
- The reserved-word escape hatch is `--table-name <name>`, not a quoting
  flag. tina4-python#123 resolved the deferred quoting question as REJECTED
  (see Resolution): Tina4 never quotes identifiers, so no `--quote` path
  ships and the inert flag that named it is removed.

## Supersedes

None. This ADR adds a new contract; no earlier ADR spoke to import
error messaging or generate output shape.
