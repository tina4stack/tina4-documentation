# ADR-0057: GIS is one PostGIS-first Point contract in every framework

- **Status:** Accepted
- **Date:** 2026-08-17
- **Scope:** Feature 137, GIS spatial points and queries
- **Decision owner:** Andre van Zuydam

## Context

Tina4 has a tested Python GIS prototype, but it sits on an old feature branch. PHP,
Ruby and Node.js have no matching implementation. Without one contract, each port can
choose a different coordinate order, storage type, distance unit, null rule or failure
policy. Those differences create valid-looking but wrong maps.

GIS also has an unbounded edge. Geometry engines support points, lines, polygons,
projections, raster data and hundreds of predicates. Shipping all of that at once would
delay the useful core and weaken its tests.

## Decision

Tina4 3.13.104 ships one GIS contract in all four backend frameworks:

1. The first field is `PointField`. Persisted line and polygon fields are deferred.
2. PostgreSQL with PostGIS is the first supported engine. Other engines fail with an
   error that names the engine and the missing spatial capability. Tina4 never replaces
   a spatial query with a latitude/longitude approximation.
3. The default SRID is 4326. Public coordinate pairs always use `(longitude, latitude)`;
   GeoJSON uses `[longitude, latitude]`.
4. Distances and radii use metres. PostGIS `geography(Point, SRID)` supplies spheroid
   distance behavior and a GiST index.
5. Values accept a Point object, a two-number coordinate pair, WKT/EWKT, GeoJSON Point
   or Feature, and WKB/EWKB. Invalid, non-finite or out-of-range coordinates fail before
   SQL runs.
6. All spatial values and query geometry are bound parameters. Identifiers pass through
   the framework's identifier guard. User input never enters spatial SQL as text.
7. The common query surface provides radius filtering, distance selection, distance
   ordering, intersection and bounding-box filtering. Each language keeps its normal
   method casing.
8. Distance ordering adds the model primary key as a stable tie-break unless the caller
   supplies or disables one.
9. ORM serialization emits GeoJSON Point geometry. Models can emit a GeoJSON Feature;
   an ordered model collection can emit a FeatureCollection.
10. One `gis_contract.json` fixture drives all four runners against a real PostGIS
    instance. SQLite may act only as the negative unsupported-engine control.

## Public surface

| Concept | Python | PHP | Ruby | Node.js |
| --- | --- | --- | --- | --- |
| Value | `Point` | `Point` | `Point` | `Point` |
| Field | `PointField` | `PointField` | `point_field` / `PointField` | `{ type: "point" }` / `PointField` |
| Radius | `within_distance` | `withinDistance` | `within_distance` | `withinDistance` |
| Distance column | `select_distance` | `selectDistance` | `select_distance` | `selectDistance` |
| Distance order | `order_by_distance` | `orderByDistance` | `order_by_distance` | `orderByDistance` |
| Intersection | `intersects` | `intersects` | `intersects` | `intersects` |
| Bounding box | `bbox` | `bbox` | `bbox` | `bbox` |
| Feature | `to_feature` | `toFeature` | `to_feature` | `toFeature` |

Names follow each language. Inputs, outputs, SQL meaning, units, errors and side effects
do not change.

## Consequences

- A charger, vehicle or device location uses the same model and query behavior in every
  Tina4 backend.
- The first release stays small enough to mutation-test in full.
- Applications that need stored geofences or route geometry must wait for a later
  `GeometryField` contract. They may still pass polygons to `intersects` as bound query
  geometry in 3.13.104.
- MySQL Spatial, SQL Server spatial types and SpatiaLite require separate provider
  evidence. Their later addition cannot change this public API.

## Rejected alternatives

- **Latitude then longitude:** WKT, PostGIS and GeoJSON use longitude first. Hiding that
  order would create silent swaps at every boundary.
- **Two numeric columns as a universal fallback:** this cannot preserve SRID, spatial
  indexing or correct geography predicates. It would return plausible wrong answers.
- **A broad `GeometryField` in the first release:** no current requirement earns the
  extra parser, DDL and query surface.
- **Different GIS APIs per database:** a provider choice must not rewrite application
  code. Unsupported engines fail until they implement the same contract.
