# ADR-0050: One buffered response, strict recursive JSON, explicit representation types

Date: 2026-08-10
Status: Proposed
Supersedes: ADR-0019's response-type clauses (status preservation across a type helper,
and the 429 representation shape). ADR-0019's rate-limiter clauses are superseded
separately by ADR-0049, and its routing-surface security intent otherwise stands. Full
contract: `features/030-response-types.md`.

## Context

ADR-0019 fixed one response-type defect (a status set before a type helper reset to 200)
and named the RFC 6585 429 shape. The feature 30 re-audit found the surrounding model is
four different products: returned strings sniff to HTML, invalid JSON (NaN, cycles,
unsupported objects, oversized integers) serializes to a value or an empty 200, nested
ORM/DatabaseResult values lose data or emit a memory-address string, helpers commit to
the socket at different points, redirects accept CR/LF, header maps are case-sensitive,
and file() loads whole files into memory or lies about a directory.

## Decision

- **One buffered response builder** per request. Helpers set representation, status and
  fields and return the same builder; none writes to the socket. Feature 31's finalizer
  commits once after Feature 33's after-hooks unwind. (Overrides Node write-on-call and
  PHP send() I/O.)
- **Automatic selection is explicit.** A returned string is `text/plain`; HTML requires
  `html()`. There is no markup sniffing and no integer-as-status. Null/no return is 204;
  an explicit `json(null)` is a 200 with body `null`.
- **Strict recursive JSON.** Compact UTF-8, `application/json` with no charset, direct
  Unicode, insertion order preserved. NaN/Infinity, cycles, non-string keys, unsupported
  objects and integers outside +/-(2^53-1) raise a `ResponseSerializationError` before
  commit; nothing stringifies or returns an empty 200. ORM models, DatabaseResult and a
  documented `to_response_data` protocol normalize recursively at any depth.
- **Status preservation.** An omitted helper status preserves the current status; it
  never resets to 200. Valid final status is 200-599.
- **Bodyless once.** HEAD and 204/205/304 carry no content, decided in the one finalizer.
- **Validated redirects and fields.** Redirect accepts 301/302/303/307/308 and a
  control-free URI; header names/values with CR/LF/NUL are rejected; singleton fields are
  case-insensitive and Set-Cookie accumulates.
- **Bounded file delivery.** file() serves only a readable regular file, applies root
  confinement and traversal rejection, streams instead of loading, and generates RFC 6266
  attachment names.

## Consequences

- Breaking, permitted before 3.14: strings stop sniffing to HTML, invalid/oversized JSON
  now fails loud, the Node/PHP commit moves to the finalizer, one file() signature, and
  Ruby drops csv()/add_cors_headers() from the response surface.
- Gated by `response_types_contract.json`, four thin runners and real-socket/ORM/file
  integration tests in the build phase.
