# ADR-0106: class-level Frond globals are read live at render time, and the auto-wired i18n `t()` is one of them

- Status: Accepted
- Date: 2026-11-17
- Supersedes: ADR-0052's clause "Existing flattened-at-construction lookup
  remains unchanged", for GLOBALS only. Filters and tests keep that clause.
- Context: a skills audit found that a template global registered through the
  documented API did not reliably reach the engine `response.render(...)` uses,
  in all four frameworks. Cross-framework contract change.

## Context

Every Frond engine copied the class-level globals once, when the engine was
constructed. `response.render(...)` builds its engine lazily, at the first
render, and then keeps it for the life of the process. So:

- A class-level `Frond.add_global(...)` / `Frond::addGlobal(...)` made after the
  first render never reached a page (Python, PHP, Ruby, Node). PHP was worse:
  its response engine can exist before any render, so ordering mattered even
  then.
- Ruby's `Tina4.template_global` and `Tina4::Template.add_global` wrote only to
  the legacy `Tina4::Template` store, which the Frond engine behind
  `response.render` never reads, so such a global rendered empty. The
  auto-wired `t()` was registered the same way, so `{{ t("key") }}` was empty
  in every `response.render` page.
- Node put the auto-wired `t()` on `startServer`'s own engine, not on the one
  `res.render` builds, so `t()` was missing from `res.render` pages.
- The auto-wired `t()` refused a params map in Python and Ruby:
  `{{ t("welcome", {"name": n}) }}` raised (`TypeError` / `ArgumentError`).
- Ruby also pinned a call to a name that was not callable yet as a plain
  variable lookup, so `{{ shout("hi") }}` stayed empty after `shout` was
  registered.

The documented workarounds were framework-specific (`Tina4.get_frond.add_global`,
`Response::getFrond()->addGlobal`), which is exactly what a parity contract is
meant to remove.

## Decision

1. A Frond engine resolves globals in four layers, lowest first: built-ins <
   class globals < this instance's own globals < the data passed to `render`.
   The class layer is read from the class registry AT RENDER TIME, not copied
   at construction. A class registration therefore reaches every engine that
   renders after it, including engines that already existed. Registration order
   never matters.
2. An instance `add_global` stays local to that engine (ADR-0052 is unchanged
   here). An instance global overrides a class global of the same name, on that
   engine only.
3. The framework auto-wires `t()` as a CLASS-level global when locale files
   exist and no `t` is already registered (class-level, or on the response
   engine). It accepts `t("key")` and `t("key", {params})` - a params map
   passed positionally - in all four frameworks.
4. Ruby's `Tina4.template_global` / `Tina4::Template.add_global` also register
   on the Frond class, so they reach `response.render`.
5. A call to a name that is not callable yet is never memoised as a variable
   lookup, so a callable registered later is called (Ruby; Python, PHP and Node
   already behaved this way).
6. ADR-0085 auto-calling of a bare zero-argument callable global is unchanged
   and applies to a late class registration exactly as to an early one.

Filters and tests are out of scope: they are still drained into an engine when
it is constructed (ADR-0052's clause stands for them).

## Consequences

- No public API is removed. Python keeps `engine._globals` as a mapping (now a
  `ChainMap` over instance, class and built-in layers); PHP's `getGlobals()`
  returns the effective set and gains `getInstanceGlobals()`; Ruby gains
  `Tina4::Frond.class_globals`; Node gains `Frond.hasGlobal(name)`.
- One extra mapping merge per render. Negligible next to tokenising or
  rendering.
- `frond_extensibility_contract.json` gains three invariants, proven by a real
  route rendered through the real request path in each framework:
  `tests/test_frond_globals_reach_render.py`,
  `tests/FrondGlobalsReachRenderTest.php`,
  `spec/frond_globals_reach_render_spec.rb`,
  `test/frondGlobalsReachRender.test.ts`.
