# ADR-0037: The no-skip gate is a deny-list, not a two-axis allow-list

- **Date:** 2026-08-04
- **Status:** Proposed - the inversion is safe to turn on only once each
  framework's skip roster is down to the entries listed under "Acceptable".
- **Scope:** The `TINA4_REQUIRE_SERVICES` gate in all four frameworks:
  `tina4-python/tests/conftest.py`, `tina4-php/Tina4/Testing/RequireServicesGate.php`,
  `tina4-ruby/spec/spec_helper.rb`, `tina4-nodejs/test/_serviceGate.ts`.
- **Relates to:** [ADR-0034](ADR-0034.md) (a test never asserts on a
  server-global metric) - same family of defect: a green that was never earned.

## The problem, measured

All four gates have the identical shape. A skip FAILS the run when its reason
matches a **service keyword** AND an **unavailable hint**:

```
is_provisioned_service_skip(reason) =
    any(keyword in reason) AND any(hint in reason)
```

Both sides are allow-lists, and they are ANDed. A reason that misses **either**
axis passes green. The hint list is identical in all four, all eight entries:

```
"not reachable", "unreachable", "not running", "not set",
"not installed", "could not connect", "not available", "refused"
```

Three leaks, each measured on the lab on 2026-08-04, not reasoned about:

### 1. A reason that misses the hint axis passes green

`tina4-php/tests/DatabaseUrlCredentialsTest.php:64` skips with the literal
string:

    live PostgreSQL not configured (TINA4_TEST_PG_URL)

`postgres` is on the keyword axis. `not configured` is on no hint list. The
gate does not fire. PostgreSQL is provisioned and running; the test skipped
green. "not configured", "unconfigured", "no credentials", "disabled",
"unsupported on this platform" and any future wording are all equally invisible.

### 2. Firebird is excluded in all four, on a premise that is false

Every gate carries a comment asserting Firebird is not provisioned, so its skips
must stay green. Node states it in code:

```ts
const EXCLUDED_KEYWORDS = ["firebird"];
```

`tina4-lab-firebird` has been running **Firebird 5.0.4 on port 3050** the whole
time. Verified 2026-08-04 with a real round trip - connect, `CREATE TABLE`,
`INSERT`, `SELECT`, `COMMIT`, `DROP` - from Python (`firebird-driver`) and Ruby
(`fb`), as both `SYSDBA/masterkey` and `tina4/tina4`. **31 tests across the four
frameworks were skipping behind a comment that was simply out of date**
(Python 8, PHP 17, Ruby 6 by reason string; Node 7 more).

The exclusion was not wrong when it was written. It became wrong, silently, and
nothing could tell anyone - which is the point.

### 3. Node could not count skips at all

`tina4-nodejs/test/run-all.ts` captures each test file's stdout and prints it
**only when the file fails**. A skip inside a passing file therefore left no
trace anywhere: the grand total had no skip component, and grepping a complete
run log for `SKIP` returned **zero lines**. Measured baseline:

    Grand Total: 7317 passed, 0 failed across 251 files

- not because nothing skipped, but because the runner had discarded the
evidence. Python prints `26 skipped`, PHPUnit `Skipped: 36`, RSpec `8 pending`;
Node printed no skip number at all. Fixed in this pass - the runner now prints
`N skipped` and lists every skip with its file and reason.

### The common shape

An allow-list gate is exactly as good as its enumeration, and every one of these
was a **missing entry that read as a pass**. That is the wrong default for a
gate whose entire job is to stop a green that was not earned.

### The same error, inverted: a "read but not set" grep is a HYPOTHESIS

The investigation that produced this ADR started from an analysis - **not the
worker's, the coordinator's** - that diffed the `TINA4_TEST_*` names the four
suites READ against the names `lab-env.sh` SETS. It found **67 read but never
exported**, and framed that as a large configuration gap: twelve services
running, test variables for about four.

Tracing every one of those 67 to its call site before exporting anything, the
real number was **three**:

| Variable | Why it mattered |
| --- | --- |
| `TINA4_TEST_FIREBIRD_URL` | the only name whose absence hard-SKIPS (python 8, php 17, ruby 6, node 7) |
| `TINA4_TEST_POSTGRES_URL` | a DIFFERENT name from `TINA4_TEST_PG_URL`, read only by PHP, 3 hard-skip sites |
| `TINA4_TEST_FIREBIRD_PATH` | PHP verifies a server-created database with a LOCAL `file_exists()` |

The other ~64 fall into four groups, none of them a gap:

- **Already correct by default.** The overwhelming majority are `DEFAULT`-valued
  and their defaults already resolve to this lab - `127.0.0.1` plus the standard
  port. Exporting them changes no test's behaviour while looking like it had.
- **Fixtures the test sets itself.** `TINA4_TEST_MODE`, `TINA4_TEST_ENV_DB_URL`,
  `TINA4_TEST_FROM_CUSTOM`, `TINA4_TEST_FROM_DEFAULT`. Exporting the last two
  would have **broken** the dotenv round-trip test, which asserts a value that
  appears only after `loadEnv()` reads it from a file.
- **Negative-test controls.** `TINA4_TEST_NO_REDIS_DRIVER` selects the branch
  under test; setting it flips the test into the wrong one.
- **Grep artifacts.** `TINA4_TEST_PG_`, `TINA4_TEST_MSSQL_`, `TINA4_TEST_MYSQL_`
  are string-concatenation prefixes, not variable names at all.

This is the same failure as the gate above, pointing the other way. The gate
trusted an enumeration of ACCEPTABLE SKIP REASONS and missed the ones nobody had
thought of; this analysis trusted an enumeration of MISSING VARIABLES and counted
64 that were not missing. In both directions the list was treated as the evidence
when it was only ever the hypothesis.

> **A name that appears in a grep is a question. The call site is the answer.**

The cost of getting this wrong is not neutral. A variable exported because it
appeared in a grep, that no test reads the way the exporter assumed, is **worse
than the skip it was meant to fix**: the skip is gone from the count, so it reads
as coverage, and nothing anywhere says otherwise. That is precisely the shape
this ADR exists to stop.

## The decision

> **Fail on ANY skip whose reason is not explicitly recognised as acceptable.**

Replace the two ANDed allow-lists with one small deny-list. The gate becomes:

```
acceptable = any(pattern in reason.lower() for pattern in ACCEPTABLE_SKIPS)
fail unless acceptable
```

Same env flag (`TINA4_REQUIRE_SERVICES`), same four call sites, same reporting.
Only the polarity changes. A new skip wording is now **caught by default**
instead of ignored by default, and the way to let one through is to add it to
`ACCEPTABLE_SKIPS` with a justification - a visible line in a diff that a
reviewer can argue with, rather than silence.

`SERVICE_KEYWORDS` and `UNAVAILABLE_HINTS` are deleted. They are not needed:
under the inversion the question is no longer "does this name a provisioned
service" but "is this skip one we have agreed to tolerate".

## Acceptable skips, with the justification each must carry

Derived from the measured baseline, not invented. Every entry names why the test
genuinely cannot run rather than why nobody got round to it.

| Pattern | Why it is acceptable | Where |
| --- | --- | --- |
| `running as root` | `chmod 0400` does not deny root, so no real `EACCES`/`SQLITE_READONLY` can be produced. Fixable only by running the suite as a non-root user. | py 1, php 2 |
| `cannot test missing extension error` | An INVERTED negative test: it skips *because* the extension IS installed. It can never run on a fully-provisioned box, which is the box we want. | php 3 |
| `drive-letter form` / `POSIX-shaped` | Platform-specific by construction - the four-slash absolute form is POSIX; Windows uses a drive letter. Correct to skip on the other platform. | cross |
| `zero-dependency run by design` | The driver variant is deliberately absent; the skip IS the assertion. | cross |
| `needs a real MinIO` | MinIO is the one service the lab genuinely does not run. Either provision it or keep this entry - but say which. | py 2 |
| `ext-interbase not installed` | The `ibase_*` API left PHP core in 7.4 and has no PHP 8 build: Ubuntu 24.04's `php8.3-interbase` package ships **only** `pdo_firebird.so`, and both `ibase_connect` and `fbird_connect` are absent. Unrunnable on any supported PHP. See "Consequences". | php 8 |

Anything not on this list fails the run.

## Prerequisites - why this could not simply be switched on

1. **Every runner must report a skip count and the reason for each.**
   **A gate cannot deny-list what it cannot enumerate.** A deny-list decides per
   skip reason, so a runner that does not surface skip reasons cannot be gated
   at all - and Node's did not (leak 3). Fixing `run-all.ts` to count and list
   skips is therefore a **precondition of this ADR, not an incidental cleanup**:
   without it Node cannot adopt the decision, and a gate that holds in three of
   four frameworks is the same partial enumeration this ADR is about. Measured
   the moment it landed: 14 skips that no run log had ever shown, four of them
   unconditional placeholders (`skip("PostgreSQL live connection", "Requires
   running PostgreSQL server")` with no condition), whose wording also dodges the
   old hint axis - invisible twice over.
2. **The baseline must already be at the acceptable set.** Inverting against a
   36-skip roster fails every run on day one and gets reverted within a week.
   Drive the roster down first, then invert - in that order. Status at the time
   of writing: **ruby 0, python 3, node 14, php 20** (from 8 / 26 / unmeasurable
   / 36). Ruby and Python are already at their acceptable sets; PHP is not, and
   its dominant blocker (12 skips on `ext-interbase`) needs a decision, not a
   configuration change - which is why this ADR stays Proposed.

## Consequences

- A newly-introduced skip fails CI until someone justifies it in
  `ACCEPTABLE_SKIPS`. That is the intended cost.
- The `ext-interbase` row is a **finding, not just a tolerated skip**:
  `tina4-php/Tina4/Database/FirebirdAdapter.php:116-151` selects a native
  `ibase_*`/`fbird_*` path that cannot execute on any PHP 8 build, so PHP's
  Firebird support is `PdoFirebirdAdapter` only. The native path should be
  dropped or documented as PHP 7.x-only; keeping 8 permanently-skipped tests
  pointed at unreachable code is the worse option.
- Skip reasons become part of the contract. Reword one and the gate notices,
  which is the correct trade for the leak it closes.
- The `[[project_require_services_gate]]` line "Firebird excluded by design" and
  the identical claim in `tina4-python/CLAUDE.md` and `tina4-ruby/CLAUDE.md`
  ("Firebird excluded by design") are **false** and must be removed in the same
  pass, or the next reader re-derives the same wrong premise.
