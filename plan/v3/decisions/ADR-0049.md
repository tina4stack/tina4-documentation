# ADR-0049: Rate limiting is on by default, a token bucket, keyed by canonical client IP

Date: 2026-08-10
Status: Proposed
Supersedes: ADR-0019's skip-and-log rule for a malformed trusted-proxy entry, and
formalizes the default, wiring, wire response, storage and lifecycle that ADR-0019
left open. ADR-0019's core (key on the socket peer with a trusted-proxy allow-list,
and middleware never opens a gate) is retained. Full contract:
`features/035-rate-limiting.md`.

## Context

ADR-0019 keyed the limiter on the socket peer with a trusted-proxy allow-list and
skipped-and-logged a malformed trusted-proxy entry. The re-audit (feature 35) found
the default was four different products (Node always-on, Python env-gated, PHP/Ruby
never wired), that health probes sat behind the limiter (a real Node `/__health`
reached 429 after two requests and could restart a healthy container), that invalid
config produced fallback/denial/crash/NaN across the ports, that a malformed forwarded
address from a trusted proxy still became the bucket key, that each port owned several
independent stores, and that process-local storage multiplied the advertised quota by
worker count.

## Decision

- **On by default** with a generous limit of 240 per 60 seconds (native integer `0`
  disables; any positive value overrides). Health/readiness and valid CORS preflight
  always bypass, so an always-on limiter cannot exhaust probes.
- **One atomic token bucket** per canonical client IP: capacity = limit, refill =
  limit/window tokens per second, monotonic clock, O(1) per key. A rejected attempt
  consumes no token. One process has one policy and one bucket-store owner; public
  middleware and service APIs delegate to it.
- **Validated configuration fails startup** (this supersedes skip-and-log): an invalid
  limit, window or provider URL, and any malformed or mixed trusted-proxy entry, stop
  the process. A malformed request forwarding chain is ignored as a whole and the
  socket peer is used.
- **Storage by URL scheme** (ADR-0024): `memory://` is the single-process default;
  `memory://` with more than one worker while limiting is enabled fails startup rather
  than silently multiplying the quota. A shared deployment uses an atomic provider such
  as Redis.
- **Provider outage is fail-open** plus a bounded error diagnostic and a
  health/readiness degradation signal; it never silently falls back to per-process
  memory.
- The **429 body and rate headers are framework-owned**, applied at the final response
  unwind with CORS and `Cache-Control: no-store`. `X-RateLimit-Reset` is absolute Unix
  seconds (the epoch at which the bucket is full); `Retry-After` is the ceiling of the
  time until the next whole token, minimum one.

## Consequences

- Every application is rate-limited by default; a multi-worker deployment must set a
  shared `TINA4_RATE_LIMIT_URL`, run one worker, or disable limiting before it boots.
- The four ports collapse their multiple stores into one coordinator: Node stops
  always-on registration, PHP and Ruby gain default wiring, and invalid config stops
  producing NaN, a crash or blanket denial.
- The behavior is gated by `rate_limit_contract.json` and four thin runners in the
  build phase.
