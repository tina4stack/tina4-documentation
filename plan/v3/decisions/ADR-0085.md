# ADR-0085: A bare zero-argument callable global is invoked and its return value is used

Date: 2026-09-24
Status: Accepted
Supersedes: none (aligns Python/PHP/Ruby to Node under ADR-0004)

## Context

Frond lets an application register globals with `add_global` / `addGlobal`. A
global can be a plain value or a callable.

Node already treats a callable global reached by a bare reference as a call: the
engine invokes the function and uses its return value for both `{{ g }}` output
and `{% if g %}` conditions (`packages/frond/src/engine.ts`, `resolvePathPart`).
Python, PHP and Ruby stored the callable and used the callable object itself, so
`{% if admin_only %}` with `add_global("admin_only", fn() => false)` was always
truthy and `{{ admin_only }}` printed the callable, not its result
(tina4-documentation#90).

ADR-0004 says the best implementation prevails and parity flows both ways. Node
is the correct behaviour here, so the other three align to it.

## Decision

- A global registered through `add_global` / `addGlobal` whose value is a bare
  zero-parameter callable is invoked when a template refers to it by name. The
  return value is used for `{{ g }}` output and for `{% if g %}` truthiness.
- "Bare zero-parameter callable" is exact per language, and matches Node, which
  auto-calls plain functions only:
  - Python: a function or method (`inspect.isfunction` / `inspect.ismethod`)
    whose signature declares zero parameters.
  - PHP: a `Closure` whose reflection reports zero parameters.
  - Ruby: a `Proc`, lambda or `Method` whose `arity` is zero.
  An arbitrary object that merely happens to be callable — a callable string,
  an `__invoke` / `__call` / `call` object — is not auto-called. This keeps the
  F6/ADR-0077 rule that request-supplied data can never name a function to run.
- A callable global that declares parameters is left as it is. It is not called
  by a bare reference; it is invoked only through `g(args)`.
- `g()` keeps working and calls the global exactly once. The explicit
  function-call path invokes the registered callable directly, so a bare
  reference and an explicit call never combine into a double call.
- Calling once is idempotent for the reader: a global that returns a callable is
  called once and yields that inner callable; the inner callable is not then
  called.
- The scope is globals only. Ordinary context variables, filters,
  functions/macros, and method or member access on objects keep their current
  behaviour. A callable passed in the render data is not auto-called.
- An unregistered `nope()` stays falsy — it resolves to an empty/undefined value
  rather than raising. This is existing behaviour in all four; the fixture pins
  it so it stays consistent.
- Node is the reference and does not change. Its behaviour gains a guard test
  only.

The Python, PHP and Ruby implementations wrap a qualifying global in a small
marker at registration (`_CallableGlobal` / `FrondAutoGlobal` / `AutoGlobal`).
The bare-reference resolver invokes the marker once; the marker forwards a real
call, so `g()` is unaffected. Node needs no marker because its resolver already
auto-calls any function member.

Node's superset — it will call any function on a bare reference, passing
`undefined` for declared parameters — is left unchanged. For the zero-parameter
global this ADR governs, all four produce the same result; the strict-arity
languages simply decline to call an argument-taking global on a bare reference,
which is the safer half of Node's behaviour and never observable for the
contract cases.

## Consequences

Before 3.14.0 this is breaking for code that registered a zero-parameter
callable global and relied on a bare reference yielding the callable object
rather than its return value. Such code calls the global explicitly with `g()`,
or registers the value instead of a callable.

The shared `frond_globals_contract.json` fixture and its four named suites gate
the seven cases: a zero-argument global returning false is falsy in an `if` and
returning true is truthy; a bare reference prints the return value; `g()` still
works; a non-callable global is unchanged; a global returning a callable is not
double-called; and an unregistered `nope()` is falsy.
