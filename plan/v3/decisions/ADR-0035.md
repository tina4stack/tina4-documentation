# ADR-0035: Tina4 SUPPLIES the uniform spelling on both providers; it does not delete it

- **Date:** 2026-08-04
- **Status:** Accepted
- **Supersedes:** [ADR-0025](ADR-0025.md) **corollary 1 only.** The core rule and
  corollaries 2, 3 and 4 stand unchanged.
- **Scope:** `DocStore` in all four frameworks - specifically what
  `get_collection` returns for the real provider.
- **Relates to:** [ADR-0024](ADR-0024.md) (the swap must work),
  [ADR-0012](ADR-0012.md) (settle contracts against real-world frameworks).

## What is being amended, and what is not

ADR-0025's core rule stays exactly as written:

> The fallback imitates the driver. Every method, signature, return shape and
> sync/async character on the fallback must exist, with the same meaning, on the
> real provider.

Corollary 3 (sync/async character does not change with the provider) and
corollary 4 (a query matching on one provider matches on the other, or the
fallback raises) also stay. Both were bought with measured defects and neither is
in scope here.

Only **corollary 1** is superseded. It read:

> **No fallback-only public method.** If Mongo has no `find_one`, neither do we.

## The problem with corollary 1

The goal is right: no method that works on the fallback and breaks on the driver.
The means was wrong. Corollary 1 deleted the method when it could have supplied
it on both sides.

Tina4's promise is "one framework, four languages - learn one, know all four". A
developer moving between the frameworks should find the same methods. ADR-0025
optimised for driver fidelity instead, and removed working API to get it. Python
kept `find_one` (pymongo has it), Ruby lost it, PHP lost `->insertedId` and
`$cursor->toList()`. The same DocStore, four different call sites.

## The decision

> A method may exist on the fallback only if it also exists, with the same
> meaning, on **what `get_collection` returns for the real provider**. Where the
> driver lacks it, Tina4 MAY supply it on BOTH sides via a delegator - never on
> the fallback alone.

The comparison target moves from the RAW driver to the RETURNED object. That is
the whole change, and it is the honest target: the object `get_collection` hands
back is the only surface a call site ever touches.

## Why a delegator, and why ADR-0025's objection does not apply

ADR-0025 costed "Option B: wrap the driver" and its lead objection was:

> A wrapper covering only today's 12-14 shared methods makes every other driver
> capability unreachable - `aggregate`, `bulkWrite`, `createIndex`, `watch`,
> sessions, transactions.

**That objection is fatal to a FACADE and irrelevant to a DELEGATOR, and a
delegator was never considered.** A facade re-declares each method it supports,
so everything it omits disappears. A delegator forwards everything untouched and
adds one method. Ruby's `SimpleDelegator` and PHP's `__call`/`__get` are the
language-native forms; both are stdlib.

Recording this plainly is the point of the ADR. A cost table that rejected the
wrong design is exactly the thing an ADR should stop from recurring.

Measured 2026-08-04 against a real MongoDB 7.x, through the delegator:

| capability ADR-0025 said would be lost | reachable through the delegator |
| -------------------------------------- | ------------------------------- |
| `aggregate`                            | yes, ruby and php               |
| `bulk_write` / `bulkWrite`             | yes, ruby and php               |
| `indexes` / `createIndex`              | yes, ruby and php               |
| `watch`                                | yes, ruby and php               |
| `with_options` / `withOptions`         | yes, ruby and php               |

Two of ADR-0025's five objections also die under this shape:

- **"Four wrappers to write and maintain."** It is TWO small classes in Ruby and
  ONE in PHP. Python needs nothing at all - pymongo already has `find_one` - and
  Node is out of scope (below). It is one wrapper in the framework whose driver
  is the outlier, not four.
- **"Python would have to REGRESS to adopt it."** It does not. Python is
  untouched.

The remaining objections are answered rather than dismissed. "It inverts the
dependency" does not hold for a delegator: the driver's API is not redefined, it
is forwarded, so a driver upgrade is not a merge problem. "It contradicts
ADR-0012" does not hold either: the driver spelling remains authoritative and
present on both providers; the uniform spelling is ADDITIVE, never a replacement.

## What is restored, and where

Restorations are **additive**. The driver spelling stays, because it is the
driver's spelling and idiomatic in its language. Both must give the same answer.

| # | framework | restored | still works |
| - | --------- | -------- | ----------- |
| 1 | ruby | `collection.find_one(filter, projection = nil)` | `find(filter).first` |
| 2 | ruby | `cursor.to_list` | `cursor.to_a` |
| 3 | php | `$cursor->toList($length = null)` | `$cursor->toArray()` |
| 4 | php | `$result->insertedId` (property) | `$result->getInsertedId()` |

Implementation:

- **ruby** `MongoCollection < SimpleDelegator` adds `find_one` and wraps `find`;
  `MongoView < SimpleDelegator` adds `to_list`. `MongoView` re-wraps on
  forwarding because a `Mongo::Collection::View` is IMMUTABLE - every
  `sort`/`limit`/`skip` returns a NEW view, so without re-wrapping `to_list`
  would vanish the moment a call site chained.
- **php** `DocStoreDelegator` adds `toList()` and a `__get` that resolves a
  uniform property name to the driver's getter. It wraps what the driver returns
  as well, because a cursor and a result object are where those spellings live.
  BSON values are never wrapped: a `BSONDocument` is DATA a call site
  subscripts, and wrapping it would break `$doc['field']`.
- **php fallback** the four result classes share one `DocStoreResultAccessors`
  trait. The backing properties stay PRIVATE, so there is still exactly one
  mechanism and no public property reappears.

**One defect this found, which only a real driver could have shown:** PHP's
`__get` first tried `property_exists()`. A real `MongoDB\InsertOneResult` has a
PRIVATE property literally named `$insertedId` behind `getInsertedId()`, and
`property_exists()` answers true for a private property - so the property branch
was taken and PHP raised "Cannot access private property", on the real provider
only. The getter is now tried first, and public properties are detected with
`get_object_vars()`, which from outside the class returns exactly what a call
site could have read itself.

## What is deliberately NOT restored: Node's cursor

Node's `Cursor[Symbol.iterator]` and `Cursor.toList()` stay removed.

A real MongoDB `FindCursor` is **async-only**: it has `Symbol.asyncIterator` and
no `Symbol.iterator`. A synchronous iterator cannot exist on the Mongo path, so
restoring it on the fallback alone would recreate ADR-0025's WORST measured
defect - identical source changing TYPE, with a truthy Promise passing
`if (doc)` for a document that does not exist. That is corollary 3, which stays.

This is the amendment working as intended rather than an exception to it. The
rule is "supply it on BOTH sides"; where both sides is impossible, the method
does not come back. `toList` appears once in
`packages/orm/src/docstore.ts` and it is a COMMENT explaining the removal, not a
live method - verified 2026-08-04. Nothing on Node's fallback is fallback-only.

## Consequences

- `docstore_contract.json`'s `the-call-site-surface-is-identical` invariant keeps
  its PROVEN status, with its harness re-pointed at the WRAPPED surface. Its case
  list changes: `the fallback only spelling is gone` is replaced by
  `the uniform spelling works on both providers`, and
  `the fallback surface resolves on the wrapped driver` is added - a MEASURED
  comparison of the fallback's public methods against what `get_collection`
  returns, rather than a hand-kept list that drifts.
- Every restoration is asserted by USE against both a real MongoDB and the SQLite
  fallback in the same case. A delegator that answers `respond_to?` and then
  raises would sail through a reflection check, so reflection is not the gate.
- **The changelog entries announcing these removals are DELETED rather than
  reversed.** Verified against `git tag`: at `3.13.94`, the last tag in all four
  frameworks, `find_one`, `to_list`, `toList` and the public `insertedId` all
  still EXISTED, and no entry announcing their removal was present. The removals
  never reached a user. Announcing a break and then announcing its reversal, in a
  release where neither shipped, makes the changelog less trustworthy.

## Still open, measured and recorded here so it is not mistaken for closed

Neither is caused by this ADR and neither is closed by it. Both need a
`find()`/`Cursor` redesign rather than a delegator method:

- **php** the fallback `Cursor` carries `sort`, `limit` and `skip`;
  `MongoDB\Driver\Cursor` has none of them, because PHP's driver takes them as
  `find()` OPTIONS and returns an already-executed cursor. The framework's own
  documented chain `$orders->find([...])->sort('total', -1)->limit(10)` therefore
  works on the fallback and fatals on the real provider.
- **ruby** the fallback `Cursor#sort(key, direction)` takes two arguments;
  `Mongo::Collection::View#sort(spec)` takes one and raises `ArgumentError` on
  two. The hash spelling `sort({key => direction})` is the single form both
  providers accept.

Both are recorded in the PHP and Ruby harnesses next to the assertions, and the
PHP one is pinned to its measured value so a change in it is noticed rather than
absorbed.
