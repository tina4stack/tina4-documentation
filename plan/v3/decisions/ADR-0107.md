# ADR-0107: class-level Frond filters and tests reach engines that already exist

- Status: Accepted
- Date: 2026-11-17
- Supersedes: what remained of ADR-0052's clause "Existing flattened-at-construction
  lookup remains unchanged". ADR-0106 removed it for globals; this ADR removes it
  for filters and tests, so the clause no longer applies to anything.
- Extends: ADR-0106 (the same rule, applied to filters and tests).
- Context: ADR-0106 left filters and tests drained into an engine once, at
  construction. Cross-framework contract change.

## Context

`response.render(...)` builds its engine once and keeps it. A filter or test
registered on the class (`Frond.add_filter` / `addFilter`, `Frond.add_test` /
`addTest`) after that engine was built never reached a page, in Python, PHP,
Ruby and Node: `{{ "hi"|loud }}` stayed `hi` and `{% if 4 is quad %}` stayed
false. In PHP the response engine exists from `App::start()` on, so even a
registration made before the first render but after boot was lost.

## Decision

1. A Frond engine resolves filters as built-ins < class filters < this
   instance's filters, and tests as class tests < this instance's tests. These
   are the same layers as globals (ADR-0106).
2. The class layer is current at every render. A class registration therefore
   reaches every engine that renders after it, existing engines included.
   Registration order never matters.
3. Instance `add_filter` / `add_test` stay local to their engine (ADR-0052). An
   instance registration overrides a class one of the same name on that engine,
   and it keeps overriding after later class changes.
4. Mechanism: filter lookup is on the hot path (once per filter application),
   so filters and tests do not use a per-lookup chain like Python's globals
   `ChainMap`. Each engine keeps a merged plain map. It rebuilds that map at
   the start of a render only when a class-registry version counter has moved
   since the last merge. A class `add_filter` / `add_test` / `clear_registry`
   bumps the counter. A per-lookup `ChainMap` measured about 1.4 µs per lookup
   against 0.06 µs for a plain dict in Python.
5. The framework-template engine copies only the user engine's INSTANCE
   filters. Class filters already reach it.

## Consequences

- No public API is removed. PHP gains `getInstanceFilters()` (mirrors
  `getInstanceGlobals()`). `getFilters()` returns the effective set, current at
  the time of the call.
- A render costs one integer comparison. A rebuild happens only after a class
  registration, which is rare after boot.
- `frond_extensibility_contract.json` gains two invariants, proven by a real
  route rendered through the real request path in each framework, in the same
  suites as ADR-0106.
