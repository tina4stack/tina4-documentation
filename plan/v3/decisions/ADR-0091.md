# ADR-0091: tina4-go templating - port Frond, do not wrap html/template

Status: Proposed (open decision for the maintainer)
Date: 2026-10-01
Context: scoping spike, `plan/go/ARCHITECTURE.md`
Relates to: ADR-0005 (Frond tracks Twig and Jinja2), the Frond spec `plan/v3/02-FROND-*.md`

## Context

Frond is Tina4's own Twig and Jinja2 compatible engine, built from scratch in all
four frameworks and sharing one template syntax, one filter set (snake_case filter
names regardless of host language), `SafeString` auto-escaping, `{% cache %}`
fragment blocks, `{% raw %}`, and the `csp_nonce()` global. A template written for
the Python app renders byte-identical under PHP, Ruby and Node, because the four
Fronds implement the same spec, not because they share code.

Go ships `html/template` in its standard library. It escapes, it is fast, and it is
free. The temptation is to wrap it. But `html/template` is its own language:
`{{.Name}}`, `{{range}}`, `{{if}}`, pipelines with a fixed function set. It does not
speak Twig's `{% for x in items %}`, `{{ value|filter }}`, template inheritance
(`{% extends %}` / `{% block %}`), or Frond's cache and nonce tags. Wrapping it
would mean translating Twig to Go-template syntax on the way in, and the first
template that uses inheritance or a Frond filter with no `html/template` equivalent
breaks the contract.

## Decision (proposed)

Port Frond. tina4-go implements the same Frond spec the other four implement -
tokenizer, parser, node evaluator, the shared filter set, `SafeString`, fragment
cache, `{% raw %}`, `csp_nonce()` - so a template renders byte-identical to the
Python reference. The TEMPLATE OUTPUT and the filter contract are what the fixtures
gate (`frondtags_contract.json`, `frond_extensibility_contract.json`,
`tina4css_contract.json`), with Go added as a fifth `suites` column.

`html/template` is NOT the engine, but its escaping primitives and its
context-aware escaper are vetted, security-critical code. Where Frond needs
HTML/attribute/JS/URL escaping, reuse Go's `html` and `html/template` escaping
helpers rather than hand-rolling an escaper (the one place a stdlib primitive is
the lean and the safe choice, per the reuse ladder).

## Open questions for the maintainer

- Confirm port-Frond over wrap-`html/template`. The recommendation is port; the only
  argument for wrap is less code today, and it cannot hold the inheritance + filter
  contract.
- Which Frond master leads the Go port - the Python reference, or whichever of the
  four has the cleanest already-decomposed engine (tokenizer / parser / evaluator /
  filters split) to mirror?

## Consequences

- Frond is a real subsystem to build in Go, not a thin adapter. It is one of the
  larger phases in the roadmap.
- No change to the four interpreted frameworks.
