# ADR-0045: Middleware before/after hooks use phase-specific result tables

Date: 2026-08-10
Status: Proposed
Supersedes: the "same table on every hook" clause of ADR-0014. ADR-0014's core
decision (a middleware's return value is the contract; response state is a legacy
path) is retained and strengthened. Full contract:
`features/007-middleware-pipeline.md`.

## Context

ADR-0014 made an explicit returned Response the primary answer and applied one
result table to every hook. A real nested unwind shows before-hooks and
after-hooks cannot share one table: an after-hook runs while outer cleanup is
still owed and must not be able to cancel it, and status-sniffing (treating a
response whose status is >= 400 as a short-circuit) turns an unrelated response
mutation into control flow. The re-audit (feature 7) also found four ports
carrying a `[request, response]` pair-rebind return that the two mutable
framework objects make unnecessary.

## Decision

Before-hooks and after-hooks use DIFFERENT result tables.

- Before: `Response` answers and stops descent at any status; `false` denies
  (explicit response, else canonical 403); null/nil/undefined continues; anything
  else is a protocol error -> clean 500.
- After: `Response` replaces the current response; null/nil/undefined keeps it;
  `false` or anything else is a protocol error -> clean 500. An after-hook can
  never cancel cleanup already owed to an outer layer.

Response-status sniffing is removed: null means continue, and a middleware that
wants to answer returns a Response or `false`. Pair rebinding `[request,
response]` is removed from both tables; hooks mutate the framework request and
response in place, and response replacement is the `Response` row.

## Consequences

- The middleware surface shrinks by one return shape on both tables plus the
  status path, consistent with removing blocks, two-argument filters and dedup.
- Python, PHP, Ruby and Node each migrate their result handling; a migration note
  ships for code relying on status-sniffing or pair rebinding.
- The behavior is gated by `middleware_contract.json` and four runners in the
  build phase.
