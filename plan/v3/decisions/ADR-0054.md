# ADR-0054: Frameworks consume metrics; the native CLI owns metrics

- **Status:** Accepted
- **Date:** 2026-08-14
- **Completes:** ADR-0002
- **Release:** 3.13.101

## Question

Where does metrics code live after Tina4 adopts one native, language-agnostic engine?

## Decision

The Rust `tina4 metrics` command owns every code-health calculation. It owns
LOC, complexity, maintainability, coupling, duplication, test detection,
offender ranking, thresholds, output, and CI exit codes.

Python, PHP, Ruby, and Node do not expose their own `metrics` command. They do
not calculate a quick census. They do not rank offenders. They do not preserve
formula tests copied from the Rust engine.

Dev-admin keeps two routes because the dashboard still needs data:

- `/__dev/api/metrics/full` calls `tina4 metrics --json` and shapes the chart payload.
- `/__dev/api/metrics/file` calls the same engine for one source file.

The file adapter preserves the native numeric function count as `function_count`
and exposes the native function records as `functions`. The browser uses that
array to render its complexity bars.

These routes are adapters, not metrics engines. They fail with a clear 503 when
the native CLI is missing or stale. A bad file path returns the existing
client-error response. There is no fallback.

## Why

One number needs one owner. Four local implementations created four answers,
four test suites, and a recursion path when an old global CLI delegated back to
a framework command.

The dashboard remains useful. The framework stays lean. The native engine owns
the arithmetic from source file to CI gate.

## Consequences

- `tina4python metrics`, `tina4php metrics`, `tina4ruby metrics`, and
  `tina4nodejs metrics` are removed in 3.13.101.
- Developers run `tina4 metrics` directly.
- Dev-admin requires a current native `tina4` CLI on PATH for its metrics tab.
- Framework tests prove the real handoff and failure path. Rust tests prove formulas.
- The former `quick_metrics` / `quickMetrics` endpoint is removed.

## Supersedes

None. This ADR completes the removal and adapter boundary already chosen in ADR-0002.
