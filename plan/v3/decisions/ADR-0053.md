# ADR-0053: One zero-dependency app-facing AI client contract

Date: 2026-08-14
Status: Accepted
Supersedes: none (resolves Feature 135 and supersedes the narrower, unimplemented proposal in tina4-python#109)

## Context

Tina4 applications repeatedly hand-roll provider-specific LLM HTTP calls. The four
frameworks currently expose developer tooling around AI, but none exposes an API for
application code to call a model. Feature 135 designed that missing surface.

The earlier tina4-python#109 proposal used `Llm.ask`/`ask_json` and deliberately
excluded streaming and embeddings. No framework shipped that proposal. The approved
3.13.101 scope instead adopts Feature 135's `Ai` surface, includes streaming and
embeddings, and defers vision and image generation.

## Decision

- The public class is `Ai`, with `chat`, `complete`, and `embed`. Vision and image
  generation are not part of 3.13.101.
- `chat` returns a normalized `ChatResponse` containing `text`, `model`, `usage`,
  `finish_reason`, and `raw`. Node.js uses its idiomatic `finishReason` property;
  wire/configuration names remain unchanged.
- `complete` is the single-user-message convenience path and returns text.
- `embed` accepts one string or a list of strings and returns one vector or a list of
  vectors with matching cardinality.
- `stream=true` returns ordered text deltas. A request may retry only before the first
  delta has been yielded.
- Providers in 3.13.101 are `local`, `openai`, and `anthropic`. `local` and `openai`
  share the OpenAI-compatible adapter; Anthropic has its own payload and normalizer.
- Runtime dependencies remain zero. Each framework uses its standard-library HTTP,
  JSON, TLS, and streaming facilities; provider SDKs are forbidden.
- Configuration precedence is explicit call argument, then environment, then default,
  as required by ADR-0041.
- `TINA4_AI_TIMEOUT` is a total request deadline and
  `TINA4_AI_CONNECT_TIMEOUT` is the connection deadline. The two meanings never
  overlap.
- `TINA4_AI_KEY` is read from the environment, is never returned by inspection or
  included in logs/errors, and is required before any hosted-provider request is sent.
  Local OpenAI-compatible endpoints require no key. TLS verification remains enabled.
- Retries are bounded by `TINA4_AI_MAX_RETRIES`, apply only to transient connection
  failures, HTTP 429, and HTTP 5xx responses, and honour bounded `Retry-After` delays.
  Other 4xx responses and malformed successful responses are not retried.
- Failures raise one documented Tina4 AI error family consistently; an empty response
  never represents a failed request. This follows the existing fail-loud read/client
  principle and keeps outages distinguishable from valid empty model output.
- Conformance uses a real local HTTP server over real sockets. Client collaborators are
  never mocked. An optional service-gated smoke may target a live OpenAI-compatible
  model, but the deterministic contract does not require a paid provider key.

## Consequences

This is a new public surface and can land without compatibility shims before 3.14.0.
The unimplemented `Llm.ask`/`ask_json` proposal is not added as a second API. Structured
JSON output, tool calling, agents, conversation state, RAG, vision, and image generation
remain outside 3.13.101 and require their own audited decisions if later justified.

The shared `ai_client_contract.json` fixture and one real-socket runner in each framework
gate the public surface, providers, response shape, configuration, security, timeout,
retry, embedding, and streaming rules.
