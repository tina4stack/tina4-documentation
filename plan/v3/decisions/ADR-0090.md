# ADR-0090: tina4-go ORM - the wire contract ports unchanged, the field API is a fresh idiomatic design

Status: Accepted (2026-10-01)
Date: 2026-10-01
Context: scoping spike, `plan/go/ARCHITECTURE.md`
Relates to: ADR-0008 (a property name is a column name), ADR-0043 (paginate envelope), ADR-0064 (ModelCollection), ADR-0067 (drivers are app dependencies)

## Context

The four frameworks declare a model's columns four different ways already. Python
hands you field objects (`IntegerField`, `StringField`). Ruby calls DSL methods
(`integer_field :id, primary_key: true`). PHP sets public array properties
(`$fieldMapping`, `$foreignKeys`). Node fills a `static fields = {}` object of
string types. ADR-0004 settled that this surface is allowed to be idiomatic per
language; what may NOT drift is the behaviour a developer or a client SEES.

Go is statically typed with no field objects and no runtime class body to read.
The natural Go shape is a struct with tags, the same mechanism `encoding/json`
already uses:

```go
type User struct {
    tina4.Model
    ID    int    `tina4:"primary_key,auto_increment"`
    Name  string `tina4:"required,max=120"`
    Email string `tina4:"unique"`
}
```

Reflection reads the tags once at registration and builds the same column map the
other four build from their own declarations. Generics (`Repository[User]`) can
give `Find`, `Where`, `All` a typed return without an `any` cast.

## Decision

- The DEVELOPER API is fresh and idiomatic: struct tags read by reflection for the
  column map, PLUS generics for typed queries (`Find`, `Where`, `All` return typed
  rows, no `any` cast). It mirrors no single sibling verbatim; it is closest to
  Node's descriptor approach but typed. Generics are worth the small extra core
  surface because compile-time typed rows are the whole reason to be in Go.
- The WIRE and STORAGE contract ports UNCHANGED and is gated by the existing
  fixtures, with Go added as a fifth `suites` column:
  - the paginate envelope is the seven snake_case keys of ADR-0043
    (`pagination_contract.json`);
  - `ModelCollection` carries a true-COUNT total and `ToPaginate()` (ADR-0064);
  - the `tina4_migration` and `tina4_sequences` table schemas are identical;
  - connection strings keep their format and the SQLite slash-count rule;
  - DB operations FAIL LOUD (return an `error`, never a silent zero value), and a
    write with no filter is an error (the 3.13.94 contract);
  - a column name is the property name, never silently rewritten (ADR-0008) - in Go
    the `tina4` tag or the exported field name is the column, and the JSON key stays
    snake_case regardless of the Go field's PascalCase.
- Drivers are app dependencies (ADR-0067): the core carries `database/sql` and the
  developer imports the `database/sql` driver they need. SQLite has no stdlib
  driver - see the open question.

## Resolved (2026-10-01)

- **Tags + reflection AND generics.** Reflection builds the column map from the
  `tina4` struct tags at registration (the dynamic feel the other four have);
  generics give typed `Find`/`Where`/`All`. Both, not either.
- **Default SQLite driver: `modernc.org/sqlite` (pure Go).** `database/sql` has no
  stdlib SQLite driver, so SQLite is an app dependency per ADR-0067 and the default
  dev database stays SQLite (no divergent zero-config default for Go). `modernc.org/
  sqlite` is chosen over `mattn/go-sqlite3` because it is pure Go: it keeps
  `CGO_ENABLED=0`, static binaries and clean cross-compilation (Go's core strength
  and the "smallest distribution" goal), where cgo would break all three. It is a
  third-party module, but it sits in the app's dependency set (ADR-0067), never in
  the framework core, so the zero-dependency-CORE promise is intact.
- **PBKDF2 (the password contract, shared with the future auth ADR): hand-write it.**
  Go's PBKDF2 lives in `golang.org/x/crypto`, outside the core tree. Rather than pull
  that module, tina4-go implements the 260000-iteration PBKDF2-SHA256 loop directly on
  `crypto/hmac` + `crypto/sha256` (both core stdlib) - a small, well-understood,
  fully-auditable loop (~20 lines) that keeps the zero-dependency-core promise
  literally true, exactly as Ruby/PHP/Node use their own stdlib crypto.

## Consequences

- A `go` column is added to `ormbase`, `ormfields`, `pagination`, `relationships`,
  `softdelete`, `migrations` and the other ORM fixtures as the port proves each.
- No behaviour change to the four interpreted frameworks.
