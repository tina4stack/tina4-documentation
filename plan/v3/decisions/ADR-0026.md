# ADR-0026: The document store is named for the CATEGORY, never for one of its backends

- **Date:** 2026-08-03
- **Status:** Accepted
- **Scope:** The name of the `DocStore` subsystem (Feature 95) in all four
  frameworks, and the naming rule for any future two-provider subsystem.
- **Relates to:** [ADR-0024](ADR-0024.md) (the swap must work),
  [ADR-0025](ADR-0025.md) (the fallback imitates the driver),
  [ADR-0012](ADR-0012.md) (settle contracts against real-world frameworks).

## The decision

> **`DocStore` keeps its name. A subsystem with more than one provider is named
> for the CATEGORY of thing it is, never for one of its backends - not the
> vendor, and not the development fallback.**

## Why this was raised

The name was convention, not a decision, so it got re-litigated. `LocalStore`
was proposed and rejected. Recording it here so the next reader does not have
the same conversation a third time.

## Why not `LocalStore`

**It names the development backend, not the thing.** In production `DocStore`
talks to a remote MongoDB cluster. A name that says "local" would be false at
exactly the moment it matters.

**It encodes the single root cause of every defect this subsystem has had.**
Nine defects were measured against a real MongoDB on 2026-08-01 and closed over
2026-08-03. Every one of them has the same shape:

| defect | symptom |
| ------ | ------- |
| php `->insertedId` | works locally, `null` on Mongo |
| ruby `find_one` | works locally, `NoMethodError` on Mongo |
| node sync -> Promise | works locally, a truthy Promise on Mongo |
| the client-per-call leak | invisible locally, exhausts the server on Mongo |
| array queries | match nothing locally, match on Mongo |

Every one is *the SQLite fallback being treated as the real thing*. Naming the
subsystem `LocalStore` would tell every developer precisely that, and make the
production path the surprise. It is the opposite of what ADR-0024 enforces.

**It collides with a live concept in the same product family.** tina4-js already
owns local-storage semantics on the frontend: `src/storage/persist.ts` exports
`persist()` and `clearPersistedKeys(keys, kind: 'local' | 'session')` over the
browser's `localStorage`. A backend `LocalStore` sitting beside that is a real
ambiguity inside one stack, not a hypothetical one.

**The industry term is the category term** (ADR-0012's authority order). CouchDB
calls itself a document store; MongoDB, Firestore and DynamoDB are all
categorised as document databases. No mainstream framework names a two-backend
abstraction after its development backend.

## What was also considered

- **`DocumentStore`** - identical meaning, no abbreviation. A legitimate option
  if the abbreviation ever reads as jargon; rejected only because the rename is
  churn without a behaviour change.
- **`Collections`** - reads well and matches Meteor/Mongo vocabulary, but loses
  the "this is a store with providers" framing.
- **`MongoStore`** - honest about the API shape after ADR-0025, but bakes a
  vendor into a name whose default backend is not that vendor.

## The cost that was NOT the deciding factor

Counted 2026-08-03, so a future rename is costed rather than guessed: 67 files
across five repos (python 14, php 13, ruby 9, nodejs 9, documentation 22), plus
breaking `Tina4::DocStore`, `Tina4\SqliteCollection`, the
`tina4_python.docstore` module path and the `@tina4/orm` exports.

Worth noting for any future proposal: **`getCollection()`, the function
developers actually call, contains no "DocStore" at all.** A rename hits internal
class names, module paths and docs - not the everyday call site. So cost is not
the reason to keep the name. Correctness is.

## Consequences

- The generalisation applies beyond this subsystem: `Database`, `Queue`,
  `Session` and `Cache` are already category names over pluggable backends, and
  stay that way. A future subsystem with two providers is named the same way.
- The naming tension ADR-0025 created is accepted deliberately: the NAME is the
  generic category, the CONTRACT is specifically the MongoDB driver's. That is
  coherent under ADR-0012 - one API, two providers, and the API is the
  mainstream one rather than an invented third shape.
